## Release policy and concrete next steps

1. **Separate correction from status upgrade.** Source-backed dates, coauthors, book titles, wording corrections and clearly falsified universal claims should be edited first, while any unsupported *interpretive* attribution remains visibly UNRESOLVED. Do not silently upgrade an entire biography for verifying one narrow fact.
2. **PR #212 must be repaired before release:** Sanders (1977 pp.75/409), Stuhlmacher (2001), Westerholm (2004) and Wright (1997) need original author passages for their exact interpretations; Seifrid also needs argument-page scope; Schreiner's Westerholm authorship correction is supported but its interpretive passages require care. See [#212 reconciliation](https://github.com/imanisworld/religion-knowledge/blob/research/law-and-covenant-20261020/docs/research/pr212-source-gate-reconciliation-20261020.md). Do not merge as-is.
3. **Use generated artifacts and verified tests:** after editing `Cited_Persons.md`, run `npm run build:readers -- --output .`, `npm run build:search-index`, any normalized-record builders, `npm test`, reader-sync validator and CI; verify desktop/mobile bibliography and search behavior and link targets. The public reader and search index must match canonical markdown; **do not hand-edit generated HTML**.
4. **History of interpretation vs underlying facts:** religious apologetics, ancient partisan witnesses, philosophy, archaeological claims and developmental psychology must remain bounded to what evidence actually establishes.
5. **Review gate:** an independent reviewer should inspect exact source editions/passages and opposing scholarship; where governance allows limitation acceptance, get and record **specific owner acceptance** for the particular claim. The source register cannot substitute for such review.
6. **Deployment:** merge only approved integrated PR(s), verify actual production deployment after CI, and keep private audit tracking out of ordinary public UI links.
