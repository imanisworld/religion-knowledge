# Provenance Specification

Provenance is a hard data-integrity requirement. The application must never present AI-generated interpretation as the user's own words, question, belief, or adopted position.

## Existing corpus markers

The uploaded corpus already uses explicit provenance markers including `⟨YOURS⟩`, `⟨DOCUMENTED⟩`, and `⟨INFERENCE⟩`. Those markers are source evidence and must be preserved.

Older sections that explicitly predate the convention or are described as mixed must remain `REVIEW_REQUIRED`; ownership must not be reconstructed from writing style.

## Normalized provenance types

- `MY_WORDS` — text explicitly authored by the user.
- `MY_POSITION` — a conclusion or belief the user explicitly adopts.
- `MY_QUESTION` — a question explicitly raised by the user without implying resolution.
- `CLAUDE` — text authored or introduced by Claude.
- `CHATGPT` — text authored or introduced by ChatGPT.
- `SOURCE` — material attributable to scripture, a book, article, scholar, historical source, video, person, website, or other external source.
- `INFERENCE` — interpretation or synthesis generated by AI and not explicitly stated by the user.
- `REVIEW_REQUIRED` — provenance cannot be established from explicit evidence.

## Representation types

- `VERBATIM`
- `PARAPHRASE`
- `SUMMARY`
- `INFERENCE`

Provenance and representation are separate dimensions. For example, a record may have provenance `CLAUDE` and representation `INFERENCE`.

An item classified as `INFERENCE` may not be represented as `VERBATIM`.

## Attribution evidence

Every classified record should retain the reason for the attribution. Valid methods include explicit exported roles, speaker labels, author metadata, message delimiters, headings, provenance markers, and other deterministic source structure.

Invalid methods include tone, vocabulary, grammar, assumed worldview, or writing-style guesses.

If the evidence is insufficient, use `REVIEW_REQUIRED`.

## User-position rule

`MY_POSITION` is stronger than `MY_WORDS`. A user statement is not automatically an adopted belief. Only classify `MY_POSITION` when the source explicitly demonstrates adoption, endorsement, or a stated current position.

## Audit-history rule

Original claims, later audits, corrections, and explanations must remain separate linked records. A correction must not overwrite the earlier claim.

## Raw-source rule

The committed uploaded corpus is immutable source evidence. Normalization, tagging, summaries, topic assignment, derived HTML, and inferred relationships must exist separately and retain a traceable link back to the source file and section.
