# Provenance Specification

Provenance is a hard data-integrity requirement. The application must never present AI-generated interpretation as the user's own words, question, belief, or adopted position.

## Provenance types

- `MY_WORDS` — text explicitly authored by the user.
- `MY_POSITION` — a conclusion or belief the user explicitly adopts.
- `MY_QUESTION` — a question explicitly raised by the user without implying resolution.
- `CLAUDE` — text authored or introduced by Claude.
- `CHATGPT` — text authored or introduced by ChatGPT.
- `SOURCE` — material attributable to scripture, a book, article, scholar, historical source, video, person, website, or other external source.
- `INFERENCE` — interpretation or synthesis generated by AI and not explicitly stated by the user.
- `REVIEW_REQUIRED` — provenance cannot be established from explicit evidence.

## Representation types

- `VERBATIM`
- `PARAPHRASE`
- `SUMMARY`
- `INFERENCE`

An item classified as `INFERENCE` provenance may not be classified as `VERBATIM` representation.

## Attribution evidence

Every classified record should retain the reason for the attribution. Valid methods include explicit exported roles, speaker labels, author metadata, message delimiters, headings, and other deterministic source structure.

Invalid methods include tone, vocabulary, grammar, assumed worldview, or writing-style guesses.

If the evidence is insufficient, use `REVIEW_REQUIRED`.

## User-position rule

`MY_POSITION` is stronger than `MY_WORDS`. A user statement is not automatically an adopted belief. Only classify `MY_POSITION` when the source explicitly demonstrates adoption, endorsement, or a stated current position.

## Raw-source rule

Raw source material is immutable. Normalization, tagging, summaries, topic assignment, and inferred relationships must exist as separate records or metadata and must preserve a traceable link to the original source.
